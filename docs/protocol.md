# TriLink Protocol Specification (v1)

## 1. Protocol Overview

The TriLink protocol (`trilink/v1`) defines the wire format, message contracts, state transitions, and error codes for peer discovery, pairing, and payload transfer.

## 3. Local Transfer Endpoints

### 3.1 Initiate Transfer (`POST /api/v1/transfers/initiate`)
```json
{
  "transfer_id": "c3d4e5f6-a7b8-9c0d-1e2f-3a4b5c6d7e8f",
  "sender_device_id": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d",
  "recipient_device_id": "b2c3d4e5-f6a7-8b9c-0d1e-2f3a4b5c6d7e",
  "item_type": "file",
  "display_name": "report_2026.pdf",
  "mime_type": "application/pdf",
  "size_bytes": 1048576,
  "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "delivery_mode": "local"
}
```

Response:
```json
{
  "status": "accepted",
  "upload_token": "token_chunk_session_xyz"
}
```

### 3.2 Stream Transfer Payload (`POST /api/v1/transfers/{transfer_id}/payload`)
- HTTP headers:
  - `Content-Type: application/octet-stream`
  - `Content-Length: <size_bytes>`
  - `X-TriLink-Transfer-Token: token_chunk_session_xyz`
  - `X-TriLink-Sender-ID: <id>`
  - `X-TriLink-Signature: <sig>`
- Body: raw binary byte stream.

### 3.3 Complete Transfer (`POST /api/v1/transfers/{transfer_id}/complete`)
Response:
```json
{
  "transfer_id": "c3d4e5f6-a7b8-9c0d-1e2f-3a4b5c6d7e8f",
  "status": "delivered",
  "verified_sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
}
```

### 3.4 Transfer Cancellation (`POST /api/v1/transfers/{transfer_id}/cancel`)
Sent if either sender or receiver cancels the active transfer.

## 4. State Transitions

| Current State | Event | Target State | Notes |
| :--- | :--- | :--- | :--- |
| `created` | Start upload | `uploading` | Stream begins |
| `created` | Peer offline (remote) | `queued` | Waiting for peer availability |
| `queued` | Peer comes online | `uploading` | Resumes remote delivery |
| `uploading` | Network break / error | `failed` | Error code recorded; retryable |
| `uploading` | Cancel invoked | `cancelled` | Clean up partial files |
| `uploading` | Payload uploaded (remote) | `available` | Ready for recipient download |
| `available` | Recipient starts download | `downloading` | Remote fetch begins |
| `downloading`| Completed & verified | `delivered` | Final success state |
| `uploading` (local)| Stream complete & verified | `delivered` | Final success state (local) |
| Any non-terminal | Expiry timeout reached | `expired` | Retention policy enforced |

---

## 5. Standard Error Codes

- `INVALID_SIGNATURE`: Cryptographic signature verification failed.
- `DEVICE_UNTRUSTED`: Sender device is not paired or has been revoked.
- `FILE_TOO_LARGE`: Declared size exceeds receiver's maximum configured limit.
- `STORAGE_EXHAUSTED`: Disk space insufficient for transfer.
- `INTEGRITY_MISMATCH`: SHA-256 hash of received payload does not match declared hash.
- `PEER_BUSY`: Another active transfer is already in progress.
- `INVALID_STATE_TRANSITION`: Transfer transition requested does not match current state.
